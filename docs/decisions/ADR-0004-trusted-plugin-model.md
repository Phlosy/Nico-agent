# ADR-0004：Manifest 优先的受信插件模型

- 状态：Accepted
- 日期：2026-07-16

## 背景

平台必须通过插件注册领域角色、工具、技能、工作流、评价器和知识，同时量化逻辑不得进入核心。

## 问题

如何让插件真实注册能力，又避免任意未受信代码在 API 进程自动执行。

## 候选方案

1. 只读取 YAML，不加载实现。
2. 自动导入扫描到的所有 Python 包。
3. Manifest 校验 + 管理员安装的受信包/仓库插件 + 显式启用 + 注册事务。

## 最终选择

选择方案 3。Manifest 声明 API 版本、包 Hash、扩展清单和权限；Loader 校验兼容性后调用稳定注册接口，默认禁用。

## 选择原因

方案 1 无法提供真实能力；方案 2 供应链风险过高。显式信任和启用能追溯每次注册，并保持核心与领域分离。

## 代价

第一版不支持任意第三方插件市场；受信插件仍需代码审计，启停必须处理已有 Run 的版本固定。

## 后续影响

Goal H 建立 PluginVersion、Registration 和兼容性检查；量化插件位于 `plugins/quant-team`，核心测试加入反向依赖检查。

## 可逆性

高。未来可增加签名、隔离插件进程或 WASM，但 Manifest 和注册协议可保持。
