# ADR-0001：模块化单体控制面与独立 Worker

- 状态：Accepted
- 日期：2026-07-16

## 背景

平台包含大量强关联领域对象，但第一版团队和规模未知，同时长时 Agent Run 不应阻塞 API 进程。

## 问题

需要在开发速度、事务一致性、故障隔离和未来扩展之间选择服务拓扑。

## 候选方案

1. 从第一天拆分 Agent、Task、Memory、Plugin 等微服务。
2. 单一进程包含 API 和执行循环。
3. 模块化单体控制面，API 与持久化 Worker 分进程，共享领域包。

## 最终选择

选择方案 3。单仓库包含 FastAPI API、独立 Worker、React Web、SDK 和插件；模块依赖通过领域/应用边界约束。

## 选择原因

领域模型仍在演进，单数据库事务能保证状态和 Event 原子性；独立 Worker 又能隔离长任务、资源消耗和恢复逻辑。

## 代价

共享数据库可能形成耦合；需要严格模块边界和后台租约，无法通过网络边界自动强制所有职责。

## 后续影响

Goal B 建立两个后端入口和共同领域包。未来拆分服务前需先稳定应用接口和 Event 契约。

## 可逆性

中等。领域模块和 Provider/Tool 接口稳定后，可按模块拆进程；数据库迁移和分布式事务会增加成本。
