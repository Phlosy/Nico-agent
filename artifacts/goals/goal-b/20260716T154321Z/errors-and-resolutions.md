# 发现的问题与处理

## 宿主机端口冲突

首次真实集成启动时，宿主机 `5432` 已被其他项目占用，PostgreSQL 容器无法发布端口。将 Nico-agent 默认发布端口迁移到 15432/16379/18000/18080/19010/19011；容器内部仍使用标准端口。重跑后通过。

## Web 容器 healthcheck

初版使用 `http://localhost:8080/healthz`。Alpine `wget` 优先使用 `::1`，Nginx 只监听 IPv4，页面可访问但 Docker health 一直 `starting`。探针改为 `127.0.0.1`，并把容器 health 纳入 `dev.sh`/E2E 的失败条件。重建后为 `healthy`。

## 清理提示文案

首次 `cleanup.sh --volumes` 已实际删除三个卷，但结尾复用了默认提示。修正分支文案，并通过最小 PostgreSQL 卷重新创建/删除验证。

## 最终代码审查

审查发现健康探针和未处理异常可能回显敏感异常原文、数据库密码特殊字符会破坏手工拼接的 DSN、前端契约守卫会接受数组/非法时间戳，以及总验收未直接执行 bootstrap 和迁移回滚。分别改为固定安全错误、SQLAlchemy URL 构造、严格运行时校验，并扩充总验收链路和回归测试。

证据收口时还发现全局 `*.log` 会忽略 Goal 验收日志，与任务书的证据持久化要求冲突；已为 `artifacts/goals/**/*.log` 增加窄范围例外，并将最终总验收与清理日志纳入清单。

以上问题均已修复，无未解决阻塞。
